# 기획 반영 상태

## 검사

최종 소스의 Sequelize 매핑은 테이블 16개와 관계 선언 19개다. 서버·DB 준비 스크립트·테스트·프런트 소스를 검사해 직접 작성한 SQL 문장과 직접 드라이버 호출을 발견하지 않았다. 기능별 API 라우터 10개는 요청 값·권한 미들웨어·HTTP 응답을 다루고 모델 호출은 서비스에 둔다. 카카오와 구글은 [소셜 라우터](../src/modules/auth/social.routes.js)를 공유한다. 프로젝트 내부 모듈 간 순환 참조도 검사했다.

2026-11-16 최종 로컬 실행에서 Mocha **86개**가 통과했다. 회원 정보와 승인·권한, 소셜 인증, 가입·메일 설정 전환, 그룹별 선택·제외와 발송 결과를 검사했다. 영상 검사는 실제 FFmpeg·Nginx를 사용했고, 원본이 다른 PC에만 있는 경우와 잘못된 교체 요청도 확인했다. 메일과 소셜 인증 자동화는 테스트 편지함·모의 공급자를 사용한다.

실제 회원가입 화면에서도 Gmail을 통해 코드를 받고 가입 신청을 완료했다. 공유 DB의 회원 상태는 `pending`이고 사용한 인증코드 행은 삭제됐다. 이 확인에는 공유 DB의 유휴 세션 5개 정리와 구형 `signup_codes.sent_at` 열의 `NULL` 허용 변경이 필요했다.

## 평가 라우터

감점표의 ‘5개 이하 미인정’에 맞춰 라우터당 6개 이상을 기준으로 셌다. 메서드와 경로 조합으로 집계한 결과는 **4개 라우터, 29개 API**다. 회원 관리·인증과 관리자 그룹·메일 기능은 집계에서 제외했다.

| 라우터                                            | 기준 경로                         | API 수 | 핵심 Mocha 검증                                              |
| ------------------------------------------------- | --------------------------------- | -----: | ------------------------------------------------------------ |
| [강좌](../src/modules/courses/routes.js)          | `/api/courses`                    |      6 | 목록 필터, 관리자 생성·수정·삭제, 학생의 수정 요청 거절      |
| [강의](../src/modules/courses/lectures.routes.js) | `/api/courses/:courseId/lectures` |      8 | 영상 업로드·부분 재생, 권한 회수, 다른 강좌의 영상 요청 거절 |
| [Q&A](../src/modules/info/routes.js)              | `/api/info/qna`                   |      8 | 비공개 질문 범위, 작성자 수정, 관리자 답변 작성·수정·삭제    |
| [공지](../src/modules/boards/routes.js)           | `/api/boards`                     |      7 | 공지 작성·수정·삭제·고정, 학생 쓰기 요청 거절, 팝업 조회     |

네 라우터의 핵심 시나리오는 [API 통합 테스트](../tests/api.test.js)에 있다. [기능 통합 테스트](../tests/features.test.js)는 팝업, 실제 FFmpeg 변환과 Nginx를 통한 권한 회수 후 재생 차단도 검사한다.

강의는 강좌 라우터가 하위 주소에 연결한 독립 Express Router다. 최상위 주소만 세면 강좌·Q&A·공지 세 개다. 보고서에 강의 라우터와 강좌의 `router.use` 코드를 함께 싣고, 중첩 라우터 인정 여부는 담당 교수의 기준을 확인한다.

## 제출물 점검

- 프로젝트 폴더에는 `src`, `client`, `tests`, 실행 설정과 의존성 목록을 포함한다. 팀 공유 ZIP에는 백엔드와 React 소스가 함께 있다. 과목에서 프론트를 따로 받으므로 최종 제출 때 프론트 제출물을 구분하고 백엔드 API를 시연한다. 제출할 압축본에서 `node_modules`와 비공개 `.env`의 제외 여부를 확인한다.
- 수업의 **프로젝트 보고서 양식.hwp**에 팀명·팀원·학번, 프로젝트 개요, 라우터별 API의 요청 항목(이름·타입·필수 여부·설명), 응답 항목(깊이·값 종류·설명)과 JSON 예시를 작성한다. 라우터마다 핵심 구현 코드·간단한 설명·해당 Mocha 코드·실행 결과를 싣고 PDF로 내보낸다.
- 팀이 작성한 회의 일지를 모으고 실제 대면 회의 사진을 보고서 부록에 넣는다. 양식은 얼굴이 보이는 학우만 인정한다고 명시한다. 현재 소스 ZIP은 프로젝트 공유용이며, 보고서 PDF·회의 사진·실제 제출은 팀 작업으로 남아 있다.

## 남은 연결

1. 기존 중복 닉네임을 정리한 뒤 db:init을 실행해 닉네임 고유 인덱스를 추가한다.
2. Google Cloud OAuth 웹 클라이언트 등록·환경 변수 입력·실계정 확인.
3. 새 공통 서비스의 실제 카카오 인증 확인. 과거 실로그인 기록과 이번 테스트를 구분한다.
4. 팀 영상 공동 재생 서버·HTTPS·영구 세션 저장소가 필요하면 별도로 배포 설계.
5. 시연할 서버에서 발신 계정을 등록한 뒤 가입 인증과 학생 안내 메일을 팀 수신 주소로 확인한다. 자동 테스트는 실제 학생에게 메일을 보내지 않는다.

코드 수정 순서와 영상 교체·공유 저장소·관리자 재로그인 검토 항목은 [인수인계서](HANDOFF.md)의 ‘팀이 이어서 수정할 때’를 참고한다.
