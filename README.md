## 현재 상태 — 2026-11-16

직접 작성한 SQL을 Sequelize 모델 매핑으로 교체했다. 각 `routes.js`에는 요청·응답을 두고 같은 폴더의 `service.js` 등에 기능 함수를 분리했다.

관리자 화면은 회원·강좌 탭으로 나뉜다. 회원 탭에서 가입 항목 ON/OFF, 회원정보 수정, 역할·시청 권한을 관리한다. 아이디·닉네임·이메일 사용 설정은 가입·내 정보·관리자 수정·응답·로그인에 함께 적용된다. 목록과 상단 메뉴는 켠 항목 중 닉네임 → 아이디 → 이메일 순서로 표시한다. 표시할 값이 모두 비어 있으면 회원 번호를 쓴다. 끈 항목과 여기에 의존하는 입력·작업은 사용자 화면에서 숨기고 관리자 설정에서 다시 켤 수 있다.

비밀번호 찾기는 **미리 연결한 카카오·구글 계정 인증 → 새 비밀번호 설정** 방식이다. 관리자의 강제 초기화는 이메일 링크 방식도 지원한다. 카카오톡 공식 채팅·채널 기능은 제거했다.

회원가입에서 이메일이 켜져 있으면 학생이 입력한 주소로 6자리 코드를 보내고, 인증이 끝나면 승인 대기 회원을 만든다. 이메일을 끄면 설정된 카카오·구글 계정 인증을 거쳐 가입한다. 두 방식 모두 관리자 승인 후 로그인할 수 있다. 실제 가입 화면에서 Gmail로 보낸 코드를 입력해 공유 DB에 승인 대기 회원이 생성되는 것까지 확인했다. 개발자는 각 서버의 비공개 `.env`에 메일 발송 설정을 입력한다. [인수인계서](docs/HANDOFF.md)

공유 DB의 기존 중복 닉네임을 보존하고 닉네임 고유 인덱스만 보류한다. 앱은 새로 입력하는 중복 닉네임을 검사한다.

## 실행

Node.js 22.12 이상. `.env.example`을 `.env`로 복사하고 본인의 DB·세션 설정을 입력한다. DB 자체와 접속 계정은 먼저 준비해야 한다.

```powershell
npm.cmd ci
npm.cmd run db:init
npm.cmd run dev
```

기본 주소는 `http://127.0.0.1:3000/`. `npm.cmd start`는 React를 빌드한 뒤 실행한다. 서버 시작 때 필요한 테이블을 확인·준비한다. 중복 회원을 삭제하거나 자동으로 이름을 바꾸는 초기화 코드는 없다.

## 검사

이 PC의 전용 MySQL과 `.env.local`, FFmpeg·Nginx를 준비한 뒤 실행한다.

```powershell
npm.cmd run db:start
npm.cmd test
npm.cmd run format:check
```

Mocha 통합 테스트 55개가 통과했다. 테스트는 localhost의 `mathsite_test` 자료만 재생성하며 가입 코드는 테스트 편지함에서 확인한다.

## 공유

공백 4칸, `npm run format` 사용. `.env`, `.env.local`, `.local`, 영상·백업, `node_modules`, `dist`는 Git·공유 ZIP에서 제외한다. 새 PC의 연결 설정과 도구 준비는 [인수인계서](docs/HANDOFF.md)에 있다.
